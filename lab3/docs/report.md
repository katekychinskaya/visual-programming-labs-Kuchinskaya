### Промпт для создания сущности в Data (Часть 4.1)
AI-агент Bubble автоматически создал тип данных `Запись` при генерации каркаса со следующими полями:

Этого достаточно для требований лабы (≥3 поля разных типов).

## 6. Освоенные элементы и workflows

### Элементы Bubble:
- **Text, Button, Input** — базовые элементы
- **RepeatingGroup** — список записей
- **Group, Container** — группировка
- **Popup** — модальное окно подтверждения удаления
- **Icon, Image** — иконки
- **Star Rating** (из плагина) — оценка записей

### Workflows:
- **Create** — «Добавить запись» (создание новой записи через форму)
- **Read** — список записей с поиском (RepeatingGroup)
- **Update** — «Отметить запись» / «Снять отметку» (изменение поля `done`)
- **Delete** — «Del ask» → «Del confirm» (удаление с попапом)

### Работа с данными:
- **Data Type `Запись`** — 5 полей разных типов
- **App Data** — 4 записи
- **Privacy** — публичный доступ (publicly visible)

### Стили и переменные:
- **Global Variables → Primary Color** (#6B4E3D)
- **Styles → primary-button** — кнопка с этим цветом

## 8. Выводы

В ходе лабораторной работы я освоила **no-code платформу Bubble** и научилась:
- Генерировать каркас приложения через встроенный **AI-агент**
- Работать с визуальным редактором (Design, Workflows, Data, Styles)
- Создавать и настраивать **Data Types** с полями разных типов
- Реализовывать **CRUD** через workflows
- Создавать **Global variables** и **Styles** для единообразного оформления
- Подключать и использовать **плагины** (ачивка 2)

Самым полезным было понять, как в Bubble устроена связка **Data + Workflow + UI**: без кода можно собрать полноценное CRUD-приложение за пару часов. Самым сложным — разобраться в терминологии Bubble (RepeatingGroup, Element Event, Style, Global variable) и найти нужные разделы в новом интерфейсе редактора.

По сравнению с Node-RED, Bubble больше ориентирован на визуальное проектирование и подходит для быстрого прототипирования приложений без знания программирования.
